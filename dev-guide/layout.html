Prusti dev guide

Repository Layout

This section describes the crates located in the Prusti repository, their function, and key modules. Some important files are linked and described individually, although this list is far from complete.

Binaries

These crates relate to the runnable executables produced during compilation.

  • prusti/ - prusti-driver, which invokes the Rust compiler with Prusti callbacks set up.
    • src/callbacks.rs - the callbacks, which collect the specifications and start the verification.
  • prusti-launch/ - the binaries that users run.
    • src/bin/prusti-rustc.rs - spawns prusti-driver with the correct environment.
    • src/bin/cargo-prusti.rs - runs Prusti on a Cargo package.
    • src/bin/prusti-server.rs - starts the Prusti server.
  • prusti-server/ - Prusti compilation server, and the code that verifies the encoded program, with or without the server.
  • prusti-smt-solver/ - a wrapper around Z3 that Viper runs in its place with the use_smt_wrapper flag, to record the quantifier instantiations of Z3 and check them against bounds (see the SMT_* configuration flags).

Specification parsing

These crates relate to parsing Prusti-specific specifications in Rust code (e.g. requires, ensures, etc). These specifications are defined using procedural macros, which must be contained in their own crates, hence the additional prusti-contracts/* crates.

  • prusti-contracts/prusti-contracts/ - stubs for Rust pseudo-functions used in specifications; currently old and before_expiry. It also reexports the procedural macros requires, ensures, etc. Depending on the prusti feature, it exports either impl or internal.
  • prusti-contracts/prusti-contracts-proc-macros/ – a procedural macro crate that either forwards calls to prusti-specs (if the prusti feature is enabled) or tries to be invisible when compiling with the regular compiler (if the prusti feature is disabled). The prusti feature is set automatically when compiling with Prusti.
  • prusti-contracts/prusti-specs/ - does the specification rewriting.
  • prusti-contracts/prusti-contracts-test – a minimal test that checks that prusti-contracts can be used with a regular compiler.
  • prusti-contracts-build/ - builds prusti-contracts with the newly built cargo-prusti while Prusti is built, which produces the library and the exported specifications that verified programs use. It runs the Prusti binaries from a copy in target/prusti-contracts-build-debug (or -release), which is also where the tests run them from by default.

Common library code

These crates contain the majority of Prusti's code.

  • prusti-utils/ - utilities used across Prusti (code independent from Rust internals), e.g. the configuration flags and helpers for launching the binaries.
  • prusti-rustc-interface/ - reexports of the Rust compiler crates used by Prusti.
  • prusti-interface/ - wrapper around the Rust compiler internals that aims to provide a more stable interface (however, it fails to completely encapsulate the Rust compiler from its clients).
    • src/environment/ - most of the wrapper code lives here.
    • src/specs/ – collect type-checked specifications.
  • vir/ - VIR, Prusti's intermediate representation of Viper programs.
  • vir-proc-macro/ - derive macros for the VIR data structures, e.g. VirHash and VirVisitable.
  • task-encoder/ - the interface of task encoders, and the program they emit their outputs into.
  • prusti-encoder/ - MIR to VIR encoding.
    • src/encoders/ - the task encoders.
  • pcg/ - the PCG (Place Capability Graph) analysis of MIR bodies, included as a Git submodule.
  • prusti-viper/ - conversion of VIR to Viper AST.
  • ide/ - support for IDEs such as Prusti Assistant, e.g. the information that Prusti reports with the show_ide_info flag.
  • tracing/ - a wrapper around the instrument macro of the tracing crate.

JVM bindings

  • viper-sys – low-level (unsafe) JVM bindings.
  • viper – higher-level JVM bindings.
  • jni-gen – generator of Rust bindings to Java classes, which viper-sys uses to generate its bindings while it is built.

Testing and debugging

  • prusti-tests/ - the end-to-end tests of Prusti.
  • smt-log-analyzer/ - analysis of the trace files that Z3 writes when run by the SMT wrapper. The viper crate runs it after verification to check that the quantifier instantiations and triggers recorded in the traces stay within the configured bounds, and it can also be run on its own, see Debugging.

Deprecated or removed

  • prusti-common/ - common modules used across Prusti, including the VIR of the previous encoder.
  • prusti-filter/ - walks through Rust crates to check which are supported by Prusti (used for evaluation in Prusti publication).
  • prusti-macros/ - macros to simplify parsing code.
